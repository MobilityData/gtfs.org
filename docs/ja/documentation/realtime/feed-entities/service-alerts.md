# サービスアラート

サービスアラートを使用すると、ネットワークに混乱が生じたときに更新情報を提供できます。個々の便の遅延やキャンセルは、通常、[便の更新情報](../trip-updates)を使用して通信するするべきである。

次の情報を提供するオプションがあります:

* URL - アラートの詳細を説明するサイトへのリンク
* ヘッダー テキスト - アラートの概要
* 説明 - アラートの完全な説明。常にヘッダーと一緒に表示されます (この情報は繰り返さないでください)。

## TimeRange

アラートは、指定された時間範囲内の適切な場所に表示されます。この範囲は、乗客がアラートを確認するのに役立つ時間全体をカバーする必要がするべきである。

時間が指定されていない場合は、フィードにある限りアラートが表示されます。複数の範囲が指定されている場合は、それらすべての期間にわたって表示されます。

## EntitySelector 

エンティティ セレクタを使用すると、このアラートがネットワークのどの部分に影響するかを正確に指定できるため、ユーザーに最も適切なアラートのみを表示できます。複数のエンティティに影響するアラートには、複数のエンティティ セレクタを含めるしてもよい。

エンティティは GTFS 識別子を使用して選択され、次のいずれかを選択できます。

* 事業者 - ネットワーク全体に影響します
* ルート - ルート全体に影響します
* ルート タイプ - このタイプのすべてのルートに影響します。例: すべての地下鉄
* 便 - 特定の便に影響します
* 停留所 - 特定の停留所に影響します

1つの`informed_entity` に、上記のフィールドを複数含めることができます。1つの `informed_entity` に複数のフィールドが含まれている場合、それらは `AND` 論理演算子で結合されていると解釈されます。つまり、アラートは `informed_entity` で提供されるすべてのフィールドを満たすコンテキストでのみ適用する必要があります。たとえば、`route_id: "1"` と `stop_id: "5"` の両方が1つの `informed_entity` に含まれている場合、アラートはルート1の停留所5にのみ適用されます。ルート1の他の停留所には適用しないでください。また、他のルートの停留所5にも適用しないでください。

複数のエンティティに影響するアラートを表現する場合 (例: ルート 1 と停留所 5 の両方に対するアラート) は、`alert`に複数の`informed_entity`を追加するべきである、それぞれが影響を受けるエンティティに適用されます (例: ルート1を含む`informed_entity`と、停留所5を含む別の`informed_entity`)。

## 原因

このアラートの原因は何ですか?次のいずれかを指定してもよい:

* **原因不明**: 混乱の原因が不明である場合、またはまだ特定されていない場合に使用します。より具体的な原因を合理的に特定できる場合は、使用を避けるべきです。
* **その他の原因**: 事前定義されたオプションのいずれにも該当しない原因に使用します。
* **技術的な問題**: 車両やインフラの故障に関連する問題。例としては、機械の故障や情報システムの不具合などがあります。
* **ストライキ**: 交通事業者または運行事業者が関与する労働ストライキによって引き起こされるサービスの混乱。
* **デモ**: 公共のデモ、抗議活動、または集会によって引き起こされるサービスの混乱。
* **事故**: 衝突や脱線など、サービスを混乱させる事象。
* **休日**: サービスの変更につながる可能性のある祝日。
* **天候**: 雪、嵐、洪水などの気象条件によって引き起こされる混乱。
* **メンテナンス**: サービスに関連する計画的なメンテナンス。例としては、線路のメンテナンス、エレベーターのメンテナンス、車両のメンテナンスなどがあります。
* **工事**: サービスに関連するかどうかにかかわらず、サービスに影響するあらゆる工事。例としては、駅の工事やバス路線に影響する道路工事などがあります。
* **警察活動**: 法執行活動またはセキュリティ上の事象による混乱。例としては、捜査やセキュリティ上の脅威などがあります。
* **医療上の緊急事態**: 乗客または職員の医療上の緊急事態に関わる事象。例としては、車内での医療上の問題により列車が停止せざるを得ない場合などがあります。
* **特別イベント**: パレード、フェスティバル、公演、ファーマーズマーケット、スポーツイベントなど、一回限りまたは定期的な特別イベント。

## 影響

この問題は指定されたエンティティにどのような影響を与えますか? 次のいずれかを指定してもよい:

* **サービスなし**: 指定されたエンティティへの交通サービスがありません。
  * 事業者の場合、その事業者のすべてのルートが運行されません。
  * ルートの場合、そのルートのすべての便が運行されません。
  * 便の場合、その特定の便が運休となります。
  * 駅 (`location_type` = 1) または停留所 (`location_type` = 0) の場合、乗客は乗車も降車もできません。
* **サービス削減**: 便の数または頻度が減少します。
* **大幅な遅延**: ルートが継続的に遅れて運行されます (軽微な遅延は[便の更新](trip-updates.md)を通じてのみ提供するべきです)。
* **迂回**: ルートの経路が変更され、一部の停留所での乗車/降車に影響する場合があります。
* **追加サービス**: 便の数または頻度が増加します。たとえば、特別イベントに対応するためにバスが増便される場合などです。
* **サービス変更**: 運行は、乗客が通常期待するものとは異なります。一例として、その曜日の通常のサービスとは異なる今後の休日スケジュールを乗客に通知するアラートが挙げられます。
* **停留所の移動**: 停留所の位置が一時的または恒久的に変更されます (恒久的な変更であることがわかっている場合は、新しい位置が時刻表データに反映されていることを確認してください)。
* **その他の影響**: これらのオプションのいずれにも該当しません。
* **影響不明**: 影響がまだ特定されていないアラートに使用します。アラートの影響が判明している場合、またはアラートのヘッダーや説明から推測できる場合は、「影響不明」を使用しないでください。
* **影響なし**: アラートは乗客に情報を提供しますが、運営には影響しません。例としては、公開会議の宣伝やアンケートによるフィードバックの募集などがあります。必要な場合を除き、この影響は使用しないことをお勧めします。
* **アクセシビリティの問題**: アラートは、段差のないアクセスに影響するアクセシビリティの問題に関する情報を提供します。例としては、使用できないエレベーターや可動式スロープ、車体を傾けること (ニーリング) ができないバス、プラットフォームとの隙間が大きい列車による臨時運行などがあります。
